# 开放问题与实现假设

本文件记录接口文档、原型和当前仓库之间的差异，后续开发时必须先看。

## 1. 原型与接口枚举冲突

## 1.1 `frameworkType`

接口文档：

- `LANGCHAIN`
- `DIFY`
- `OPENAI_COMPAT`
- `CUSTOM`

原型里出现：

- `SPRING_AI`

结论：

- 首期前端只按接口文档支持
- 不要把 `SPRING_AI` 写入枚举逻辑

## 1.2 `healthStatus`

接口文档：

- `UNKNOWN`
- `HEALTHY`
- `UNHEALTHY`

原型里出现：

- `DEGRADED`

结论：

- 首期前端只按接口文档支持
- 如果后端实际返回 `DEGRADED`，再单独调整

## 2. 统计卡片缺少接口

原型列表页有统计卡片，但接口文档没有 summary 接口。

结论：

- 首期不做真实统计卡片
- 可临时移除或保留空态占位

## 3. 原型中的批量能力没有接口支持

原型出现但接口文档未定义：

- 批量下线
- 批量健康检查
- 导出
- 保存视图

结论：

- 全部视为二期
- 首期不要在代码里做假按钮

## 4. 详情页“最近操作”缺少接口

原型有最近操作时间线，但接口文档只给了发布历史，没有操作日志查询接口。

结论：

- 首期不做最近操作时间线
- 详情页只做发布历史

## 5. 分类 / 标签页面缺少使用次数接口

原型出现：

- 分类节点数量
- 标签关联数
- 同步使用次数
- 按使用次数排序

接口文档没有定义这些字段或接口。

结论：

- 首期不做这些能力
- 表格与树节点不要依赖使用次数

## 6. 标签全量选项接口缺失

表单里需要多选标签，但接口文档只定义了分页接口：

- `GET /console/agent-tags/page`

结论：

- 首期使用 `page?current=1&size=100`
- 若标签量明显增大，再向后端补充下拉专用接口

## 7. ACL 主体名称解析不是智能体接口的一部分

ACL 列表返回里只有：

- `subjectType`
- `subjectId`

是否返回主体名称不明确。

结论：

- 首期前端要准备“主体名称回填”逻辑
- 可通过当前选择器缓存或复用部门 / 角色 / 用户接口补充名称

## 8. 详情页可见范围展示存在原型内部冲突

原型 hero 区和基础信息区对同一条数据的可见范围展示不完全一致。

结论：

- 首期以后端返回为准
- 不根据原型静态文案做硬编码

## 9. 列表接口路径可能存在两种写法

接口文档写了：

- `/console/agents`
- `/console/agents/page`

结论：

- API 封装层要做一次适配
- 后续以真实联调结果固定

## 10. 健康巡检页面不在本期范围

原型左侧菜单里出现“健康巡检”，但接口文档没有给独立页面能力。

结论：

- 本期只实现详情页里的健康检查动作
- 不单独开发健康巡检菜单页
